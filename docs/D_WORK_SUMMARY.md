## 3. 研究问题与设计动机

原有 sparse 奖励只在吃到食物或死亡时给出反馈，普通移动奖励为 0。
本轮要建立能检验以下问题的实现与实验流程：

1. 加入距离变化反馈，能否帮助智能体学习寻找食物？
2. 加入小额每步惩罚，能否减少无效移动或长时间不吃食物？
3. 奖励上升时，真实吃食物得分是否也提高？

D-01 完成时仅具备检验这些问题的工具；D-03 的正式结果与限制已补充到第 11 节。

## 4. 奖励方案

### 4.1 共同基础

- 吃食物：+10，并使 Score 加 1。
- 撞墙或撞自身：-10。
- 填满棋盘：胜利，保留食物奖励，不加死亡惩罚。
- Score 是吃到食物的数量；Return 是一局即时奖励的累计，两者含义不同。

### 4.2 三个可切换方案

令 d_before 和 d_after 为移动前后蛇头到同一颗旧食物的曼哈顿距离，单位为格子：

```text
d(head, food) = |head_row - food_row| + |head_col - food_col|
distance_reward = alpha * (d_before - d_after)
```

| reward_mode | 总奖励 | 默认含义 |
|---|---|---|
| sparse | food_reward + death_penalty | 原基线 |
| distance | 原基线 + distance_reward | 靠近一格 +0.1，远离一格 -0.1 |
| distance_step | 原基线 + distance_reward - beta | 在距离反馈上，每步再扣 0.01 |

alpha 对应配置 `distance_reward_scale=0.1`，beta 对应 `step_penalty=0.01`。
二者可由命令行覆盖，并保存进配置与模型；必须有限、非负且总和小于 10。
这些系数是实验起点，不是已验证的最佳值；逐步量级受限也不代表整局累计 shaping 必然很小。

### 4.3 实现中的关键边界

| 情况 | 处理 | 原因 |
|---|---|---|
| 吃到食物并刷新 | 先用旧食物计算距离差，再生成新食物 | 避免新食物随机位置干扰本步奖励 |
| 碰撞 | 距离项为 0 | 碰撞不算成功移动，不能因虚拟落点获得靠近奖励 |
| distance_step 的最后一步 | 死亡、截断步也扣步惩罚 | 统一每个有效动作的计费规则 |
| 达到每局步数上限 | 正常计算本步奖励，不加死亡惩罚 | 保留 terminated / truncated 的区别 |
| reset | 四项奖励全为 0 | 重置不是行动，不应产生奖励 |

本方案是启发式奖励塑形，不声称具有势函数塑形的最优策略不变保证。
实现只改变奖励，不改变状态、动作映射、环境动力学或食物生成的随机数序列。

本次因环境占用修复，V1 也重新训练，没有拿同学修复前的历史成绩直接充当对照。
网络实际参数量：V1 18,435，V2 19,587，多 1,152；因此比较的是整体状态方案，含输入容量变化。

### 10.4 可以支持的分析

在当前 DQN、sparse、100k 步预算与评估条件下，V2 的平均每局得分更高，三个配对 seed 都有提升。
V2 同时有更长的平均局长，但单位步数吃食物数基本相近，因此不能直接解释为更高的寻食效率。
跨 seed 波动略大，不能把“得分更高”说成“更稳定”。两组截断率都为零，没有观察到时间上限造成的成绩截断。

距离信息与局部占用可能帮助决策，但本轮没有分拆它们，不能把收益单独归因于某一特征。
还存在参数量差异、3 个训练 seed、单一棋盘及单一预算等限制；未进行显著性检验，未证明收敛。
后续奖励实验可暂定固定 V2，在当前环境版本重新比较所有奖励模式；不宣称 V2 是普遍最优状态。

原始精度下分项之和等于 Return，表格取两位小数可能有舍入误差。

### 14.2 交互对比的定义

每个配对训练 seed 分别计算：gain(state, reward)=Score(state, reward)-Score(state, sparse)。
交互量为 gain(V2, reward)-gain(V1, reward)，即差中差，再对三个 seed 汇总均值与总体标准差（ddof=0）。
负值只表示 V2 下的 shaping 相对效应更低，不等于 V2 整体得分更低；不做未经检验的显著性或机制判断。
