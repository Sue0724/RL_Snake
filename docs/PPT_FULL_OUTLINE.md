### 第 2 页｜研究背景与选题意义

**核心信息**

贪吃蛇规则直观，但包含长序列决策、稀疏延迟奖励、动态障碍与探索利用权衡。

**放置内容**

- 交互过程：观察状态 → 选择动作 → 接收奖励与下一状态 → 更新策略。
- 规则可视化，方便定位环境或策略问题。
- 普通移动没有基线奖励，食物与死亡才提供反馈；行动代价可能延迟出现。
- 蛇身增长形成动态障碍，短期安全不等于长期安全。
- 固定配置、随机种子与动作序列，可复现环境轨迹。
- 三个问题：状态怎么表示、稀疏奖励下怎么学、算法怎么公平比较。

**建议图示**

智能体与环境交互回路，配标注状态、动作、奖励的实际棋盘截图。

**讲述重点**

本页提出问题；状态对应第 5、22 页，奖励对应第 23–24 页，比较协议对应第 9、21 页。

**建议讲稿**

### 第 3 页｜问题建模：把贪吃蛇写成 MDP

**核心信息**

以完整游戏状态描述回合式 MDP，算法使用人工压缩观测；严格区分真正终止和训练时长截断。

**放置内容**

| 元素 | 本项目定义 | 说明 |
|---|---|---|
| 状态 S | 完整蛇身位置与顺序、朝向、食物等 | V1 的 11 维向量是压缩观测，见第 5 页 |
| 动作 A | 0 直行、1 左转、2 右转 | 相对动作 |
| 转移 P | 游戏规则及食物、初始位置随机性 | 随机数由 seed 控制 |
| 奖励 R | 食物 +10、死亡 -10、普通移动 0 | sparse 基线 |
| 折扣 γ | 0.99 | 对未来奖励进行折扣 |

```text
目标：max_π E_π[Σ_t γ^t r_t]
terminated：撞墙、撞自身或填满棋盘
truncated：达到单局 500 步上限但仍未真正终止
```

```python
state, info = env.reset(seed=seed)
next_state, reward, terminated, truncated, info = env.step(action)
env.render()
env.close()
```

**建议图示**

游戏概念与 MDP 元素对应表，以及区分终止、截断的交互图。

**讲述重点**

截断仍 bootstrap。V1/V2 压缩观测不保证完整马尔可夫性。500 步是训练截断，不直接据此宣称有限时域 MDP；若剩余时间属于任务条件，应将其纳入完整状态。

**建议讲稿**

> 完整游戏状态描述环境转移，智能体实际收到的是压缩特征，这两者需要区分。还有一个影响训练正确性的约定：碰撞是真终止，达到步数上限是截断。只有真终止才去掉下一状态价值，截断仍要 bootstrap。

**建议时长**：60 秒。

**资料来源**：[接口约定](../docs/INTERFACE.md)、[DQN 实现](../algorithms/dqn.py)。

### 第 4 页｜环境实现：规则、接口与关键设计

**核心信息**

保证规则一致、训练渲染解耦，并在相同随机条件下复现。

**放置内容**

- 10×10 棋盘，初始蛇长 3、朝向向右；一个食物，从空格均匀采样。
- 相对动作排除 180° 反向，统一转向语义；未单独验证样本效率收益。
- 出界或撞身体算碰撞；普通移动允许进入当步腾出的旧蛇尾格。
- 食物不在蛇身上，因此吃食物和进入旧尾格不会同时发生；填满棋盘为胜利。
- 五元组接口；info 中 food_reward、death_penalty、distance_reward、step_reward 合计为 reward。
- 无渲染时不加载 pygame；通过 env.state_dim、env.n_actions 获取维度。
- 历史环境阶段验证：专项测试 41 项，Stage 1 验收 13/13；不是当前全量测试数。

**建议图示**

标出头、身、尾、食物和三个动作的棋盘；另画进入旧尾格的合法移动案例。

**讲述重点**

danger 特征必须与实际碰撞语义一致。D 后续修复进入旧尾格时 occupied 集合更新问题，正式对照使用修复环境重训。

**建议讲稿**

> 环境里容易忽略的是蛇尾会在同一步腾出位置。危险特征和实际移动必须一致，否则模型收到的标签就不准确。渲染也独立于训练，保证批量实验不依赖图形窗口。

**建议时长**：60 秒。

**资料来源**：[接口约定](../docs/INTERFACE.md)、[阶段清单](../docs/STAGE_CHECKLIST.md)、[状态实验与尾格修复](../docs/STATE_EXPERIMENT.md)。

### 第 5 页｜State V1：11 维基线观测

**核心信息**

V1 用紧凑人工特征提供局部危险、当前朝向与食物相对方位，作为统一基线输入。

**放置内容**

| 特征组 | 维数 | 含义 |
|---|---|---|
| 相对危险 | 3 | 直行、左转、右转后的碰撞风险 |
| 当前朝向 | 4 | 朝向的 one-hot 编码 |
| 食物相对方位 | 4 | 食物是否在头部上、下、左、右 |
| 合计 | 11 | float32 向量 |

- 食物方位不是 one-hot，斜向食物可同时激活两个方位。
- 优点：输入紧凑、语义直观，不必从像素学习基础规则。
- 局限：缺少明确距离与完整蛇身布局，不保证完整马尔可夫性。
- 本页依据已有接口补齐原稿缺页，V2 留到第 22 页。

**建议图示**

棋盘截图旁按 3+4+4 分组显示对应特征。

**讲述重点**

解释“提供什么”和“遗漏什么”，为状态扩展建立动机。

**建议讲稿**

> 基线把棋盘压缩为十一维：三个危险标记、四个朝向标记和四个食物方位标记。它容易训练和解释，但不能完整描述距离与蛇身分布。这也是后面检验 V2 的原因。

**建议时长**：45 秒。

### 第 7 页｜DQN 基线实现

**核心信息**

动作选择、经验回放、目标网络及模型保存恢复均已接入。

**放置内容**

- Online Network 预测动作价值；Target Network 提供目标值。
- Replay Buffer 保存交互，mini-batch 采样更新。
- epsilon-greedy 控制探索，目标网络周期硬同步。
- checkpoint 保存和恢复训练状态。

```text
y = r + γ(1 - terminated) max_a' Q_target(s', a')
```

**建议图示**

交互、写回放、采样、计算目标、更新 Online、同步 Target 的流程图。

**讲述重点**

解释公式各部分作用；推导放备用材料；截断不进入终止掩码。

**建议讲稿**

> DQN 用在线网络选择动作，通过回放采样训练，再用目标网络计算学习目标。它不是只拟合即时奖励，而是学习即时奖励与下一状态折扣价值之和。

**建议时长**：50 秒。

**资料来源**：[DQN 实现](../algorithms/dqn.py)、[训练入口](../train.py)。

### 第 8 页｜影响正确性的实现细节

**核心信息**

终止、探索衰减和目标同步必须有统一可验证的执行语义。

**放置内容**

| 约定 | 执行语义 |
|---|---|
| 真终止 | 碰撞等真正结束后停止 bootstrap |
| 步数截断 | 保留下一状态价值 |
| 探索衰减 | 按已完成训练环境步计数，跨 episode 延续 |
| 默认探索 | 初值 1.0，下限 0.05，衰减系数 0.9999 |
| 独立评估 | 关闭探索，纯贪心 |
| 目标同步 | 按成功梯度更新次数计数，每 1,000 次硬同步 |

**建议图示**

环境步和成功更新次数的双时间轴，标出 warmup、epsilon、同步点。

**讲述重点**

环境步不等于梯度更新次数；warmup 期间也有环境交互。

**建议讲稿**

> 参数不能只给数字，还要说明按什么计数。探索率按环境步衰减，目标同步按成功更新次数计数。所有入口使用同一约定，实验才可复现。

| Double DQN | Bellman 目标 | 缓解 max 在估计误差下可能引入的高估 |
| Dueling DQN | Q 网络结构 | 分离状态价值与动作优势，改善表征方式 |

- 顺序：动机 → 两种算法 → 接入 → 测试 → 调试 → 小结。
- 设计动机不等于本项目已证实收益，正式比较见第 26 页。

**建议图示**

训练流水线上高亮“目标计算”和“网络结构”替换点。

**讲述重点**

呼应第 6 页：替换算法组件，保持共同训练系统。

**建议讲稿**

> 我的部分研究两个切入点：Double 改目标，Dueling 改网络。我们先验证正确接入，再由正式实验检验这些设计是否带来实际得分收益。

**建议时长**：30 秒。

**资料来源**：[Double 实现](../algorithms/double_dqn.py)、[Dueling 实现](../algorithms/dueling_dqn.py)。

### 第 14 页｜Double DQN：选动作与评动作分离

**核心信息**

Online 选择下一动作，Target 评价该动作，将选择与估值解耦。

**放置内容**

```text
a* = argmax_a' Q_online(s', a')
y = r + γ(1 - terminated) Q_target(s', a*)
```

- max 在估计噪声下可能偏向高估；选评解耦用于缓解，不保证完全消除偏差。
- 只重写 _bellman_targets，其他训练逻辑复用。
- 不增加参数，但下一状态额外经过 Online 前向；未做受控速度比较。
- 真终止不 bootstrap，截断保留，与 DQN 一致。

**建议图示**

DQN 的 Target-max 单路径，对比 Double 的 Online-argmax / Target-取值双路径。

**讲述重点**

“argmax 来自 Online，取值来自 Target”；不展示未经测量的偏差幅度或速度收益。

**建议讲稿**

> Double 的关键是把选择和评价拆开。在线网络认为哪个动作最好，就让目标网络评价那个动作。改动集中在目标计算，参数不变，但多了一次在线网络前向。

**建议时长**：50 秒。

**资料来源**：[Double 实现](../algorithms/double_dqn.py)、[数值测试](../tests/test_double_dqn.py)。

### 第 15 页｜Dueling DQN：状态价值与动作优势分离

**核心信息**

共享特征后分别估计 V 与 A，通过均值中心化聚合为动作 Q 值。

**放置内容**

```text
Q(s,a) = V(s) + A(s,a) - mean_a' A(s,a')
```

- 动机：动作价值相近时共享状态价值估计；实际表现需要验证。
- 两层 FC+ReLU → Value 标量流、Advantage 动作流 → 聚合。
- 减均值约束分解，避免 V/A 任意加减相同常数。
- 新增 DuelingQNetwork，Agent 替换 network_class，其他公共逻辑复用。
- 输出仍为三个动作 Q 值；本版本沿用 DQN target，不是 Double+Dueling 组合。

**建议图示**

普通单流 QNetwork 与共享层、双流、聚合结构对照。

**讲述重点**

表征改进是目标，不直接称更稳定或更高效；V2 配置多 129 参数，见第 26 页。

**建议讲稿**

> Dueling 把状态价值和动作相对优势拆开，再减去优势均值合成 Q 值。输出形式不变，所以评估入口不需要改变。是否带来收益仍要看正式结果。

**建议时长**：50 秒。

**资料来源**：[Dueling 实现](../algorithms/dueling_dqn.py)、[接口约定](../docs/INTERFACE.md)。
